## 0. Headline facts

- **There is NO organization / tenant concept anywhere.** No `organization_id` on any of the 56 tables. Everything is global: `employees.employee_id` UNIQUE globally (20240101:8), `buses.bus_number`, `tablets.tablet_number`, `airlines.name` UNIQUE globally, `app_settings` and `ot_banner` are singletons (`id='singleton'`, 20260520000001:100, 20260525000008:67), `idx_emergency_one_active` allows exactly one active emergency for the whole database (20260525000023:15), chat rooms seeded globally. Roles are global. RLS is role-only, never tenant-scoped.
- Table set matches live exactly: 56 tables created by migrations = 56 live (plus views `latest_bus_positions`). No table drift. Function set also matches (custom_access_token_hook dropped in …04, consistent). Drift is only in **cron jobs** (4 HTTP jobs are not in any migration), Auth hook/settings, and Vault secret.
- Identity is split three ways: `profiles.role`, `employees.role`, and JWT `app_metadata.role`. FKs mix `auth.users(id)` (shifts.dispatcher_id, breaks.dispatcher_override_by, repair_notes.technician_id, *.created_by/posted_by/awarded_by/reviewed_by, notifications.user_id) with `employees(id)` (chat_*, lost_*, emergency_*, session_overrides, notification_queue.recipient_id). `profiles.employee_id` is the *text* employee number FK (20260520000001:7) while everything else uses `employees.id` uuid.
- Roles in v0 (CHECK, 20260520000001:8 and 20260520000002:12): admin, management, driver, dispatcher, coordinator, supervisor, technician, fueler_washer, payroll. Owner's new list is admin, supervisor, dispatcher, coordinator, driver, fueler, technician (no management/payroll; `fueler_washer` -> fueler).
- Login in v0 is **Supabase Auth password** keyed by employee ID (service-role lookup of email by employee_id, GUIDE.md:149-158), NOT a PIN. `employees.pin` is a leftover NOT NULL plaintext column (20240101:13), commented "DEPRECATED" (20260520000002:36) but never dropped; seed sets pin = employee_id (seed.sql:5-9). Owner wants PIN kiosk clock-in: this must be rebuilt (hashed PIN, per-kiosk, per-org).
- No time clock table exists any more: v1 `time_entries`/`timesheets`/`dvi_records` were dropped CASCADE (20260601000005:23-34). Clock in/out is now just `shifts.actual_start/actual_end` created by a dispatcher sign-in. There is no self-service kiosk clock-in in the v2 schema.

## 1. Data model

RLS legend: `HR(x)` = `has_role(ARRAY[x])`; ad=admin, mg=management, di=dispatcher, su=supervisor, co=coordinator, dr=driver, te=technician, fw=fueler_washer, pa=payroll. "own" = `employee_id = get_my_employee_id()`. All policies were mechanically rewritten to `(SELECT ...)` form in 20260622000002 (names/semantics unchanged). All 56 tables have RLS enabled; only `login_attempts` has zero policies (intentional deny-all). Policy is a single PERMISSIVE set unless noted.

## 2. Business rules encoded in SQL

**Breaks (`generate_breaks`, 20260601000001:44-110, SECURITY DEFINER, search_path=public).** Rules read from `app_settings.break_rules` (singleton), defaults in code: `duration_minutes` 15, `flex_minutes` 45, `break1_after_start_minutes` 135, `break2_before_end_minutes` 120, `default_shift_minutes` 480. Skips if shift missing or `actual_start IS NULL`. Shift end estimated as `actual_start + (scheduled_end - scheduled_start)` (+24 h if end < start) or `actual_start + 480 min` if no schedule. Break 1: `scheduled_start = window_open = actual_start + 135 min`, `window_close = + 135 + 45 min`. Break 2: `window_open = est_end - 120 min`, `window_close = window_open + 45 min`. Both `duration_minutes = 15`, status `pending`, `ON CONFLICT (shift_id, break_number) DO NOTHING` (idempotent). Always creates exactly 2 breaks regardless of shift length (a 4-hour shift gets 2 breaks; a 12-hour shift only 2). No lunch/meal-period logic although `shifts.has_lunch`/`lunch_waiver` exist and the v1 comment says "waive lunch -> 8 h, else 8.5 h" (20240101:171). GRANTed to `authenticated, service_role` (…01:112) but never REVOKEd from PUBLIC/anon (Supabase default privileges grant anon EXECUTE too): any caller can invoke it with any shift uuid (idempotent, low impact).
- Trigger `generate_breaks_on_active` (…01:133): AFTER INSERT OR UPDATE OF status, actual_start on shifts; if `status='active' AND actual_start IS NOT NULL` -> generate_breaks. Does not regenerate when scheduled times change; breaks never deleted on cancel.
- Phase 7 was a no-op bug: `UPDATE app_settings ... WHERE id='default'` (20260526000001:15) matched 0 rows; it also set breaks default to 45 and rewrote pending breaks to 45, which phase 8 reverts (…01:16-21). Net effect today: 15-minute breaks.
- Break status machine is enforced only by the Edge Function (break-monitor) and app code, not by a trigger: pending -> active -> completed; pending past `window_close` -> missed; active >= 17 min -> reminder; >= 20 min -> overrun.

**Fatigue.** DB side only notifies: `fn_fatigue_alert_notify` AFTER INSERT on fatigue_alerts (20260601000006:19-58): enqueues an `in_app` queue row to the affected employee and to every employee with `status='active' AND auth_user_id IS NOT NULL AND role IN ('dispatcher','supervisor','management')` (admins are NOT notified; comment claims email too but only `in_app`). Dedup partial unique `uq_fatigue_open_weekly (employee_id, alert_type) WHERE shift_id IS NULL AND resolved_at IS NULL AND dismissed_at IS NULL` (…06:14). Thresholds live in TS (`lib/payroll-calc.ts`): single shift >= 10 h, >5 days in ISO week, weekly OT >= 10 h (GUIDE.md:401).

**Login lockout (`register_login_attempt`, 20260601000010:23-57).** Sliding window per `attempt_key` (the action passes key and params: `app/login/actions.ts:52`; GUIDE says 5 attempts / 15 min, i.e. `p_max=5`, `p_window_secs=900`, passed by the caller, not stored in SQL). Row-locks (`FOR UPDATE`), resets count to 1 when window expired; denies when `count >= p_max` with `retry_after_min = ceil(remaining/60)` (min 1); else increments. `clear_login_attempts` deletes the row on success. Both SECURITY DEFINER with `search_path=public` and `GRANT ... TO service_role` (…10:68-69) but **no REVOKE from PUBLIC/anon/authenticated**, so the anon key can call `rpc/clear_login_attempts` to reset any key (defeating the lockout) or `rpc/register_login_attempt` to lock any employee ID out. Table never cleaned (unbounded growth). Counter is per employee ID only (not per IP).

**Auth/role helpers.** `has_role(text[])` (20260520000003:28-40): `COALESCE(jwt.app_metadata.role = ANY(roles), profiles.role = ANY(roles), false)`. If the JWT has any role claim, profiles is never consulted (stale JWT keeps old role up to `jwt_expiry` 3600 s, and a banned/terminated user keeps access until token expiry). It never checks `profiles.is_active` or `employees.status`. `get_my_role()` and `get_my_employee_id()` are SECURITY DEFINER STABLE with `search_path=public`; callable by anon (return NULL).

**Bus status log.** `trg_bus_status_change` AFTER UPDATE OF status writes a history row (from/to, current fuel_level and mileage; no actor). Repair: `trg_repair_resolved` stamps `resolved_at` on is_resolved false->true.

**GPS.** `fn_upsert_current_position` AFTER INSERT on bus_positions upserts `current_bus_positions` only if `EXCLUDED.recorded_at >= existing` (out-of-order safe). `cleanup_old_bus_positions()` deletes `recorded_at < now() - 30 days` (SECURITY DEFINER, **no search_path**, 20260525000014:29-34; executable by anon via RPC). pg_cron `nightly-gps-cleanup` at `0 3 * * *` (UTC, 20260616000001:80-84). Terminal geofences (200 m radius) are data only; no SQL uses them.

**Notification fan-out.** `fn_queue_to_notifications` AFTER INSERT on notification_queue: for `channel='in_app'`, looks up `employees.auth_user_id`; skips if null; maps 17 event types to the 15-value `notifications.type` check (break_missed->break_overdue, wheelchair_escalation->wheelchair_request, hazard_alert/emergency->emergency_alert, overtime_awarded->overtime_shift ...), unknown -> `info`; title from `payload.title` or initcapped event type; body from `payload.message|body`. Employees with no login get no in-app notification (and the queue row is still marked 'sent').

**Check constraints worth keeping** (enums as listed in §1). Others: `buses.fuel_level 0-100`; `pay_periods.period_end > period_start`; `shift_bid_awards.preference_rank 1-3`; `breaks.break_number IN (1,2)`; `app_settings` singleton check; `ot_banner` singleton by default only (no CHECK).

**Constraints missing**: no CHECK `actual_end >= actual_start` (shifts, breaks), no exclusion constraint for overlapping shifts or pay periods, no `slots_available`/`max_drivers` enforcement, no mileage monotonicity, no immutability enforcement for `is_locked`/`locked_at`/closed pay periods (closed period `daily_hours_records` still writable by admin/payroll).

## 4. Cron setup and auth

- Live jobs: notification-processor `* * * * *`, wheelchair-escalation `* * * * *`, chat-reminder `*/5 * * * *`, break-monitor `* * * * *`, nightly-gps-cleanup `0 3 * * *` (pure SQL: `SELECT public.cleanup_old_bus_positions();`).

- Auth to functions: `net.http_post(url := 'https://<ref>.supabase.co/functions/v1/<fn>', headers := {Content-Type, Authorization: 'Bearer ' || (select decrypted_secret from vault.decrypted_secrets where name='service_role_key')}, body := '{}')`. - Every minute x 3 functions + 5-min chat = ~4,300 invocations/day, each doing full-table scans of employees (no index on role/status except partial `idx_employees_active_notify`, 20260622000001:45-47, which matches only `auth_user_id IS NOT NULL`, while the Edge Functions' queries don't include that predicate, so the index won't be used by them). pg_net responses table is not pruned. No alerting if a job fails (`cron.job_run_details` only).

## 5. Migration history problems

1. **Mixed history, unclean start.** Five v1 migrations (20240101_*, 202412220000/1, 202501010001/2) create a throwaway schema (employees+vehicles+time_entries+...) with `USING (true)` for every op, then v2 overhaul drops "Allow all/public" policies via ILIKE loop (20260520000003:7-21) and finally drops the v1 tables CASCADE in 20260601000005. Replaying from scratch must therefore create-then-destroy tables; only `employees` and `safety_meeting_schedules` survive.
2. **Non-timestamp / odd versions**: `20240101_init_core_schema.sql` (8-digit) and `202412220000`, `202501010001` (12-digit) mixed with 14-digit stamps; works by lexicographic order but is not CLI-conventional. Dates in headers vs filenames disagree (…10 and …11 labelled 2026-06-16 but stamped 20260601; …06/07/08/09 labelled 2026-06-03).
3. **Non-idempotent realtime adds.** ~20 bare `ALTER PUBLICATION supabase_realtime ADD TABLE ...` (e.g. 20260525000001:103-104, …0002:42, …0014:55) error if re-run and abort the whole migration transaction; RECOVERY.md:116 calls it "safe" - it is not. Later migrations (…05, …07) use guarded blocks: inconsistent.
4. **Realtime vs docs drift**: `ot_banner` is claimed published in GUIDE.md:507 but no migration publishes it; `notification_queue` (with payloads) is published although only ad/mg may read it.
5. **Unreproducible live objects**: cron HTTP jobs, Vault secret, `pg_cron`/`pg_net` extensions, Auth hook disablement (…04 requires manual dashboard step, comment :8-11), Auth settings (signup, SMTP), storage bucket policies for other buckets. Header of 20260622000001 says indexes were "NOT applied to or EXPLAIN-verified against the live database" and the RLS wrap spec (`supabase/perf-notes/RLS_SELECT_WRAPPING.md`) says "NOT a migration" but 20260622000002 is exactly that migration: perf-notes is stale. Whether …0622 migrations are applied live is unverified here.
6. **SECURITY DEFINER without `SET search_path`**: `cleanup_old_bus_positions` (20260525000014:29), `log_lost_item_status_change` (20260525000019:52). All other definer functions set `search_path=public`. `custom_access_token_hook` was invoker, dropped.
7. **Function EXECUTE exposure**: no migration REVOKEs EXECUTE from PUBLIC/anon on any app function (only the dropped hook). Exposed to anon via PostgREST RPC: `generate_breaks`, `cleanup_old_bus_positions`, `register_login_attempt`, `clear_login_attempts` (security-relevant), `has_role/get_my_role/get_my_employee_id` (harmless). `_v2_wrap_rls_helpers` was dropped after use.
8. **Policy defects (copy-paste class):** (a) UPDATE/ALL policies with no WITH CHECK reuse USING, producing the "can't transition status" traps on `shifts` (20260525000006:77-83) and `form_submissions` (20260525000013:149-153); (b) INSERT checks that omit an owner check: `bus_positions` (bus_id), `end_of_shift_submissions` (20260525000026:27-30), `wheelchair_requests` (20260525000025:133), `chat_messages` sender; (c) `repairs_delete` uses `auth.jwt()->>'role'` (never matches), `repairs_upload/read` open to any authenticated user (20260525000026:58-67); (d) `USING (true)` with no `TO` clause means anon: `airlines_read`, `emergency_read_all`, `emergency_ack_read` (20260525000025:119,209,214); (e) `auth.uid() IS NOT NULL` reads (`buses`, `tablets`, `bus_status_history`, `overtime_shifts`, `ot_banner`, `safety_meetings`, `app_settings` via `auth.role()='authenticated'`) are effectively public to anyone who can self-register: config.toml has `enable_signup = true` and `enable_confirmations = false` (:171, :216-221) and min password length 6 (:177). Live Auth config not in repo.
9. **Duplicate/overlapping policies**: employees has five permissive policies; chat tables have one ALL policy covering everything; `profiles` admin policy only checks JWT (not has_role). `safety_meeting_schedules` went through 4 policy generations (202501010002 open -> 20260520000003 role-gated writes -> …05 `TO authenticated WITH CHECK (true)` -> 20260616000001 role-gated), leaving `sms_public_read_active` as the only read.

No index on `notification_queue(queued_at)` besides the partial pending/retry one.
12. **RLS select-wrapping migration risk** (20260622000002): regex rewrite with `[^\)]*` is safe only for helper calls without nested parentheses; it rewrote every public policy via DROP/CREATE inside one DO block (policies momentarily absent within the transaction only). `storage.objects` policies (schema storage) were NOT rewritten, they still call `has_role()` unwrapped per row.

## 7. Worst problems (ranked)

1. No tenant model at all (global uniques, singleton settings/banner/emergency): every table needs `org_id` + org-scoped RLS in the rebuild.
2. Anon-callable SECURITY DEFINER RPCs: `clear_login_attempts`/`register_login_attempt` defeat/abuse the login lockout; `cleanup_old_bus_positions`, `generate_breaks` also exposed; no REVOKE anywhere.
3. Edge functions' `verify_jwt=true` accepts the public anon key (docs claim service-role only); plus no concurrency lock in notification-processor, silent "sent" when email skipped, HTML injection via payload.message, broken chat-reminder dedup (`created_at` vs `queued_at`), wheelchair escalation bulk insert fails on null driver.
4. Plaintext `employees.pin` readable by dispatcher/coordinator/supervisor/payroll; PIN login not actually implemented in v0 (password auth by employee ID).
5. RLS gaps: missing owner checks on INSERT/UPDATE (bus_positions, EOS, wheelchair, chat sender, safety sign-ins, notifications), implied-WITH-CHECK status traps (shifts, form_submissions), `repairs_delete` never matches, anon-readable airlines/emergencies, `auth.uid() IS NOT NULL` reads with `enable_signup=true`, `has_role` ignores `is_active`/`status` and trusts stale JWTs.

7. Infra not reproducible: cron HTTP jobs, Vault, extensions, Auth hook state live only in dashboard/doc; RECOVERY.md/README stale.
