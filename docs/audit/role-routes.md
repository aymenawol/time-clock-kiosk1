# Audit: role-facing app (everything outside app/admin), lib, components, middleware

Scope: app/* except admin, middleware.ts, lib/, components/ (non-ui), scripts/, tests/, next.config.mjs. Read-only. Next 16.1 / React 19 / Supabase SSR / zod 3.25. Repo root: C:\Users\aymen\personal\rolecall.
Legend: RLS = relies on Postgres RLS only (no server check in code). "svc" = service-role client (bypasses RLS).

## 0. Headline facts (read first)

- **There is NO tenant/organization concept anywhere** in types, queries or actions. `app_settings`, `ot_banner` are `id='singleton'` rows. Whole app is single-company.
- **There is NO "clock-in/clock-out" feature for the employee.** "Clock-in" = a dispatcher/admin creates a `shifts` row (status `active`, `actual_start=now`) on the Sign-In Sheet (`app/dispatcher/sign-in/sign-in-client.tsx:105`), with driver, bus, tablet, scheduled times, lunch flags, canvas signature (base64 PNG stored in `shifts.signature_data`). "Clock-out" = driver submits End of Shift (`app/driver/actions.ts:180-196`). Breaks are DB-generated rows (`generate_breaks` RPC, migration 20260601000001). No PIN, no kiosk clock-in screen exists. **Owner decision (PIN on shared kiosk) is entirely new work.**
- **Login is NOT PIN.** Two modes on `/login`: (a) "kiosk" = numeric Employee ID (3-8 digits, on-screen keypad) + password, resolved server-side to `employees.email` then `signInWithPassword` (`app/login/actions.ts`); (b) "staff" = email + password direct from browser. `employees.pin` column is deprecated/unused (`lib/supabase.ts:62`).
- **"Tablet" = a physical device asset** (`tablets`: tablet_number, serial_number, is_available) assigned to a shift. It is not an auth principal, not a kiosk session, not device-bound. Nothing outside `submitEndOfShiftAction` ever touches `is_available`; **nothing sets it to false on sign-in** (grep: only `app/driver/actions.ts:202` writes it, `true`). The "available tablets" list therefore never shrinks (unless an admin/DB trigger outside my scope does it).
- Role lives only in `auth.users.app_metadata.role` (JWT). 9 roles: admin, management, driver, dispatcher, coordinator, supervisor, technician, fueler_washer, payroll. The product brief lists fewer/different ones (no management/payroll/fueler_washer naming; adds fueler vs fueler_washer).
- Hardcoded customer data is small: Las Vegas terminals (`lib/terminals.ts`, 4 LAS terminals + map centre), login copy "Harry Reid International Airport · Las Vegas" (`app/login/page.tsx:169`), counting-sheet columns RAC/T1/T3/Term1/Term3 West/East (LAS-specific), Nevada break policy defaults in migrations. No "Transdev" string in my scope (grep clean).
- Tests: 4 vitest files only (gps-utils, n-tasks, overtime-schema, payroll-calc: pure functions). No test touches auth, actions, RLS, middleware. No e2e in repo.

## 2. Behaviours and business rules per feature (so nothing is lost)

### Login (`app/login/actions.ts`, `app/login/page.tsx`)
- Employee ID format `^\d{3,8}$`; password required (actions.ts:67-73). Keypad max 8 digits (page.tsx).
- Rate limit: 5 attempts / 15 min per **employee id** via RPC `register_login_attempt(p_key,p_max,p_window_secs)`; fall back to in-memory Map on RPC error (actions.ts:30-60). Cleared on success.
- Terminated (`employees.status='terminated'`) get a specific message (leaks existence). Missing email -> generic error.
- After auth, role missing -> signOut + error. Success returns role; client picks home by `roleHomePath`.
- Staff mode uses browser `signInWithPassword`; error message is Supabase's raw message.
- Safe-redirect helper blocks `//` and `/\` open redirect (page.tsx:19-23). Default `redirectTo=/admin/employees` is applied to admin/management only.
- Test accounts: `scripts/link-test-logins.mjs` makes driver IDs 1001 and 1234 with password `Test1234!` and `@test.local` emails, role driver, service role. Credentials committed in repo.

### Time clock / shift lifecycle (as actually built)
- `shifts.status`: scheduled -> active -> completed | cancelled. Created `active` with `actual_start=now()` by Sign-In Sheet. (`scheduled` status is only ever read by pages; nothing in my scope creates scheduled shifts.)
- Breaks: policy in migration 20260601000001: 2 paid 15-min breaks; B1 window opens `actual_start + 135 min`; B2 opens `end - 120 min`; flex +45 min (`window_close`); reminder at 17 min, `overrun` at 20 min after start; `missed` when pending past `window_close`. `break-monitor` edge fn runs every minute and notifies dispatcher/coordinator/supervisor (missed) and dispatcher/management/supervisor (overrun). Dispatcher can re-enable: new window now..now+flex (default 45) (`app/dispatcher/actions.ts:20-45`).
- Driver: Start break (pending, inside window) sets `actual_start`, status `active`, sends radio 10-39; End break sets `actual_end`, `completed`, radio 10-8 (driver-dashboard.tsx:190-210). Countdown = actual_start + duration.
- End of shift: closes shift, `total_hours=round(wall hours,2)`, releases tablet, writes bus fuel/status, hazard alert, performance snapshot (driver/actions.ts:103-237).
- Meal/lunch: `has_lunch`, `lunch_waiver` stored on shift; **never used in hour calculation**.

### Radio codes (`app/driver/actions.ts:9-24`, `lib/constants/radio-codes.ts`)
- 10-8 -> bus `in_service`; 10-39 -> in_service; 10-37 -> `fuel`; 10-7 -> `shopped_dvir`. Notify roles: 10-8 dispatcher; 10-39 dispatcher+supervisor; 10-37 dispatcher+admin+supervisor; 10-7 dispatcher+management. Board-only labels: 10-51 Assist Needed, 10-33 HAZARD.

### Bus status vocabulary (`lib/constants/bus-status.ts`)
- 12 statuses: ready, in_service, charging, fuel, wash, fuel_wash, maintenance_pmi, shopped_dvir, maintenance_repair, safety_hold, salvage, training. OOS = shopped_dvir, maintenance_repair, maintenance_pmi, safety_hold, salvage. Available = ready.
- Transitions are NOT centrally enforced: radio (any user), fueler, technician (browser), end-of-shift, inspection flag. Duplicate maps exist in `lib/supabase.ts` (BUS_STATUS_LABELS/COLOR) and `lib/constants/bus-status.ts`.
- End-of-shift map: ready->ready, charge_required->charging, shop->shopped_dvir, hazard->safety_hold (+ alert dispatcher/management/admin). Diesel fuel labels: Full 100, Over 3/4 80, Over 1/2 60, Under 1/4 20. EV auto "charge required" when battery <50% (display only).
- Inspection with defects on submit -> bus `shopped_dvir` + notify technician/dispatcher/management (`flagBusOutOfServiceAction`).
- Fueler: fuel->ready, wash->ready, fuel_wash->(fueled)->wash, ->(washed)->fuel; others rejected; optional fuel_level 0-100 when fueling (`fueler/actions.ts:21-74`).

### Inspections
- Checklist: 11 categories / ~45 items in `INSPECTION_CHECKLIST` (`lib/supabase.ts:262-274`): Exterior, Tires, Lights, Brake Systems, Steering, Gauges, Interior, Passenger Ramp, Parking Brake, Safety Equipment, Mirrors. Items `is_ok` true/false/null; unchecked -> confirm dialog but allowed.
- Mileage: beginning/ending ints, `miles_driven` computed client-side. Damage drawing = vector strokes normalised 0..1 across 4 views front/rear/driver_side/curb_side (`lib/damage.ts`); legacy PNG/ `DamageDrawingPath` type still in `lib/supabase.ts`. Submit sets `is_locked`, `submitted_at`.
- One inspection per shift per type (read by `maybeSingle`); no unique enforcement in code.

### Counting sheet
- Rows: departure_time + 6 counters (rac, t1, t3, term1, term3_west, term3_east); default 10 blank rows; blank rows dropped on save; row total = sum. Submit sets `status=submitted`, `submitted_at`, `end_time=now` and notifies admin/management/dispatcher.

### GPS tracking flow
- Driver dashboard `watchPosition` while `shift.status==='active'`: insert into `bus_positions` (driver_id, bus_id, shift_id, lat/lng, speed km/h = m/s*3.6, heading, accuracy, recorded_at=device time) throttled to 1 write / 10 s (driver-dashboard.tsx:100-140). RLS: driver INSERT where driver_id = get_my_employee_id(); staff SELECT.
- Reads: view `latest_bus_positions` on board; realtime INSERT updates tiles; 5-sample history for ETA. `gps-utils`: haversine; ETA = distance(latest, terminal)/avg speed of last 3 samples with speed>0 (null if <1 km/h); nearest-terminal ETA; congestion per terminal: >=2 buses within 200 m yellow, >=3 red; stale >60 s.
- Issues: device clock for recorded_at; GPS stops when dashboard unmounted (navigating to /driver/inspection etc. unmounts it, no background tracking at all); no retention/cleanup; no accuracy filter.
- Motion lock (DriverShell): speed >5 mph for 8 s locks UI (military clock screen); <=5 mph for 15 s unlocks; exempt via active `session_overrides` row.

### Dispatcher board / compliance
- Break alerts list on dispatcher dashboard: breaks with status active/overrun/missed today; badge colours; re-enable button for missed/overrun.
- Coordinator verdict: ok|flag + note, stores `compliance_verdict, compliance_note, compliance_by (auth uid), compliance_at` on shift.
- Fatigue alerts (board): `fatigue_alerts` unresolved & not dismissed, limit 50 (written by admin payroll flow).

### Wheelchair 10-51
- Driver picks airline (searchable, `airlines.is_active`), passenger name, flight; row `pending`. Dispatcher responds -> `acknowledged` + `dispatcher_response`; resolves -> `resolved`. Escalation after **5 minutes** without response is done by edge fn `wheelchair-escalation` (status `escalated`); driver sees "call dispatch".

### Forms (`lib/supabase.ts:FormType`)
- Types: time_off, bid_vacation_change, incident_report, fmla_conversion, resignation. Statuses: submitted, under_review, approved, denied, returned. Employee can acknowledge a decision (`form_acknowledgements`).

### Shift bids
- Cycle status draft->published->locked->awarded. Slot: bid_number, shift_start/end, report_time, 7 day booleans, route_type (full_time, employee_shuttle, part_time), max_drivers. Employee ranks up to 3 slots; awards by seniority/manual/auto_unsubmitted (admin side). UI text: "Higher seniority employees are awarded first."

### Overtime
- OT shift: date, start_time, duration_hours (0<x<=24), slots_available (1-100), description<=2000, bid_close_at, status open/closed/awarded/cancelled. Banner singleton `{is_active,message}` shown to drivers + board. Off-day request: date + message; driver responds accepted/declined/custom (available_start_time, available_hours, custom_availability).

### Payroll / overtime / fatigue (`lib/payroll-calc.ts`)
- `calcDailyHours`: wall-clock (out - in)/h; regular = min(total, 8); OT = max(0,total-8). **Hardcoded 8 h "FLSA" (line 16-18)**; ignores `app_settings.overtime_rules.daily_ot_threshold_hours`; ignores unpaid meal breaks, lunch waiver; not calendar-day or 24-hour-period based; no Nevada wage-threshold test (daily OT only if paid < 1.5x min wage); `DailyHoursInput.missedBreaks` declared, unused.
- `calcWeeklyOT(records)`: sorts by date, cumulative regular hours capped at 40, excess moved to OT. Caller must pass one week; function itself has no week boundary; PTO/FMLA hours not counted toward the 40 (pto/fmla fields only carried through). No double-time. No 7th-day rule.
- `buildPayrollCSV`: headers fixed; escape only quotes fields containing a comma (fields with `"` or newline but no comma are not escaped); no formula-injection guard (`=`,`+`,`-`,`@`).
- Fatigue: `shouldRaiseFatigueAlert(total>=10)` single_shift; `WEEKLY_DAYS_LIMIT=5` consecutive_days; `WEEKLY_OT_ALERT_HOURS=10` ot_threshold. Header comment says ">8h/day or >5 days/week", constants say 10 h and 5 days (inconsistent). ISO week (Mon start) helpers `isoWeekKey`, `daysWorkedByWeek`, `maxDaysInAnyWeek`, `weeklyOtHours`. Admin payroll action (outside scope) uses these (app/admin/payroll/actions.ts:90-134).

## 3. Auth, roles and routing (current model)

**Identity.** Supabase Auth users. `employees.auth_user_id` links to `auth.users.id`; `employees.email` is used by the Employee-ID login to find the auth email. Role = `app_metadata.role` only. Optional `employees.role` column duplicates it (used for notification recipient queries and the sign-in driver dropdown); `profiles` table (id, employee_id, role) is a third copy (written by the script). Three sources of truth for role; code reads JWT for access, `employees.role` for targeting. They can drift.

**Session.** `@supabase/ssr` cookies. `middleware.ts` calls `getUser()` on every request (good, network-validated) and refreshes cookies. In Next 16 the file convention is `proxy.ts`; `middleware.ts` is deprecated.

**Middleware guards** (`middleware.ts`): only `/admin` (admin,management), `/dispatcher` (+admin,management,dispatcher), `/driver` (admin,management,driver), `/coordinator` (admin,management,coordinator,supervisor), `/technician` (admin,management,technician). Unauthenticated: /admin,/dispatcher,/coordinator,/technician -> `/login?redirectTo=`; /driver -> `/`. Matcher excludes `_next`, favicon, `images/`, **`safety/`** (public).
- **Not covered by middleware**: `/board`, `/chat`, `/fueler`, `/supervisor`, `/balances`, `/onboard`, `/auth/callback`, `/login`. These rely on layout/page checks, which is where gaps appear (chat has no layout guard; page guard only).
- `startsWith('/driver')` also matches `/driverX`; trivial.

**Page/layout guards.** Layout role arrays duplicate middleware (driver, dispatcher, coordinator, supervisor, fueler, technician, board). Next layouts do not re-run on every client navigation, so layout-only guards (board, fueler, supervisor) are weaker than they look; each `page.tsx` for those routes does its own query without checking role.

**Role-to-home maps** (4 copies): page.tsx `DASHBOARD_FOR`, login `roleHomePath`, callback `roleHome`, onboard `redirectByRole`. management/admin -> /admin/employees, supervisor/coordinator -> /coordinator, payroll -> /admin/payroll, fueler_washer -> /fueler.

**Concrete role bugs**
1. `payroll` role: home `/admin/payroll`, nav `PAYROLL_NAV` = /admin/payroll + /admin/reports, but middleware lets only admin/management under /admin: **payroll users get /unauthorized** (unless the admin layout/middleware is changed elsewhere; middleware is authoritative).
2. `fueler_washer` is blocked by middleware from every `/driver/*` page that their own nav and dashboard link to (forms, safety meetings, lost & found).
3. Technicians, dispatchers, coordinators, supervisors, payroll and fuelers have no route to forms, lost & found, safety-meeting sign-in, bids, performance (employees of those roles cannot submit time off, incident reports, etc.). Only /balances is role-agnostic.
4. Admin/management are allowed into /driver, then see `employeeId = user.id` fallback and actions that try to act as a driver.
5. `supervisor` and `coordinator` share `/coordinator`, supervisor gets board+chat nav; coordinator does not; `/supervisor` just redirects.
6. Dispatcher board link `/admin/map` is unreachable for dispatcher/supervisor.
7. `unauthorized` page says "Back to Kiosk".

**Security problems (ranked)**
1. **Server actions with service role and only `requireUser`** (any logged-in user, including a fueler/technician): `radioCodeAction`, `flagBusOutOfServiceAction`, `submitEndOfShiftAction` take client-supplied shift/bus ids with no ownership or role check. Result: IDOR to change any bus status, close any shift (affects payroll hours), spoof notifications. (`app/driver/actions.ts:24,69,98`).
2. **Chat service-role actions have no room membership check** (`app/chat/actions.ts`): read-receipt/confirm/send into any room; also unconfirmed count crosses rooms. Admin-only checks exist only for delete/create.
3. **Client-side writes trusted to RLS** with no server validation: shifts (sign-in), breaks, bus_positions, wheelchair_requests, inspections, repair_notes, bus status (technician), counting sheets, lost_items, emergency ack, notifications mark-read. I did not audit the RLS policies in depth; any weakness there is directly exploitable from the browser with the anon key. Ensure policies are per-column/state-machine aware.
4. **`/safety/[token]` public**: `safety_meeting_schedules` has `SELECT USING (true)`; tokens add nothing.
5. **Login**: limiter keyed by employee id only (DoS lockout of any ID; no IP/device dimension); 3-8 digit numeric IDs are guessable; terminated vs unknown messages differ; staff email login unthrottled by app. Test credentials `Test1234!` committed in script.
6. **Storage**: `repairs` bucket is public (getPublicUrl); `lost-and-found` upload has no type/size check server-side; policies not reviewed.
7. **Notification lib** exports unauthenticated service-role writers from a `'use server'` file (latent). Guard script ignores `lib/`.
8. **Role source drift** (app_metadata vs employees.role vs profiles) and no revocation: JWT role is valid until refresh (up to 1 h); terminated employee's session keeps working (no `status` check in middleware/actions except login).
9. **No tenant isolation**: every `.from('employees')` etc. is global; a second company in the same project would see everything.
10. CSP only `frame-ancestors`; no script-src. HSTS preload header set (fine). Viewport disables zoom (`maximumScale: 1`, accessibility).
11. Emergency modal and motion lock enforceable only client side; `employees` ping query on reconnect.

## 5. Cross-cutting defects and dead code

- **Timezone**: every page computes "today" with `new Date().toISOString().slice(0,10)` (UTC). For a Las Vegas operation, from 4/5 pm local onwards the app looks for tomorrow's shifts; overnight shifts and midnight-crossing hours also mis-bucket. Needs org time zone.
- **Duplicated supabase browser client creation** in ~20 components (no shared hook); each realtime component creates its own client/channel.
- `lib/supabase.ts` exports a stale singleton `supabase` Proxy using plain `createClient` (no cookie session) plus ~25 hand-written DB types that drift from schema (e.g. `Employee.pin`, `AppSettings` shapes, `SafetyMeeting` v1 vs `SafetyMeetingV3`, `DamageDrawingPath` vs `DamageStroke`).
- Dead: `lib/supabase.ts` `getSupabase/supabase` (verify unused), `Profile`, `DamageDrawingPath`, `RouteType` ok; `calcDailyHours.missedBreaks`; `myBidShifts`; `pending_status_changes`/`pending_breaks` stores; `SafetyMeeting`/`SafetyMeetingSchedule` v1 types (only public page), `components/ui/*` many unused; `app/supervisor/page.tsx` redirect stub; `getServerUserRole`.
- Realtime subscriptions without table filters (`shifts`, `chat_messages`, `bus_positions`, `fatigue_alerts`) deliver every row to every viewer (RLS-filtered, but heavy).
- Error handling: many client writes ignore `{error}` (wheelchair response/resolve, emergency ack, GPS inserts, break updates, repair note insert in inspection). Dispatcher OT actions `throw` raw DB messages to UI.
- No loading/empty states for several server pages (board/dispatcher have loading.tsx only).
- Hardcoded customer data: LAS terminal coordinates + names, login footer, counting-sheet columns, Nevada-oriented break defaults, 8 h FLSA daily OT, `meetings` departments list.
- Build gate: `package.json` build runs `scripts/check-admin-guards.mjs` (AST scan of `app` + `actions` for service-role use without `require*/assert*/ensure*` or `app_metadata`). A `requireUser()` counts as authz, which is exactly the weakness in section 3 (#1). It does not scan `lib/`.
- `next.config.mjs`: TS errors fail the build; only baseline security headers; no image/remote config; no CSP script policy.
- Mixed conventions: some actions return `{error}`, some `{success,...}`, some throw, `ActionResult` unused here.
